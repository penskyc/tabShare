## 2. Threading model + one UDP socket

SonoBus binds **one IPv4 UDP socket** (JUCE `DatagramSocket` = `socket(AF_INET, SOCK_DGRAM)`, SO_REUSEADDR, 1 MB
send+recv buffers, port 0 = OS-chosen unless the user fixes one; SBP:931-972). Everything (server UDP handshake, peer
hole-punch pings, AOO audio, `/sb/...` messages) goes over it. The TCP connection to the server is owned by the AOO
client internally.

| Thread | Priority | Loop | Calls |
|---|---|---|---|
| **Recv** | highest/RT | `waitUntilReady(read, 20 ms)` then `doReceiveData()` | `aoo_parse_pattern` / `aoonet_parse_pattern`, `sink->handle_message`, `source->handle_message`, `client->handle_message`, `/sb` parser; then `notifySendThread()` |
| **Send** | highest/RT | wait on event, 20 ms timeout, `doSendData()` (SBP:414-446, 3231) | loop `while(didsomething)`: `dummySource->send()`, `client->send()`, per peer `source->send()`, `sink->send()`, latency/echo sends, `/sb/ping` every 2 s |
| **Event** | normal | `sleep(20)`; `handleEvents()` (SBP:3341) | `client->handle_events`, `source->handle_events`, `sink->handle_events` for dummy + every peer |
| **Client** | normal | `client->run()` (blocks; SBP:513-530) | TCP connect/login/group commands, TCP ping every 10 s; returns after `client->quit()` |
| **Audio** | device | `processBlock` | `t = aoo_osctime_get()` once (SBP:7458); per peer `sink->process(...)`, `source->process(...)`; `notifySendThread()` at end (SBP:8396) |

Thread-safety contract (aoo.h comments): `process`, `send`, `handle_message`, `handle_events` are "threadsafe, but not
reentrant" (one thread each). Options, `add_sink`/`remove_sink`, `invite_source`/`uninvite_source` are always
threadsafe. **`setup()` must not race `process()`**: SonoBus wraps sink `process` in a per-peer read lock and the
format-event `setup` in a write lock (SBP:7841, 3787). Source/sink `process` are the only calls you make in the audio
callback; they don't allocate in steady state.

`client->send()` is **not optional**: it drives the server UDP handshake (`/aoo/server/request` every 100 ms until
`/aoo/client/reply`), the 10 s UDP keepalive, and all peer hole-punch pings (client.cpp:442-495). Call it from your
send loop at least every ~20 ms.

**Send/reply callbacks** (SBP:374-410):
```cpp
// AOO source/sink replies: endpoint = your per-remote-address object
static int32_t endpoint_send(void *ep, const char *data, int32_t size);          // aoo_replyfn
// AOO client: first arg is the opaque pointer you passed to iclient::create, addr is a sockaddr_in*
static int32_t client_send(void *user, const char *data, int32_t size, void *addr) { // aoo_sendfn
    auto sa = (const sockaddr *)addr;
    if (sa->sa_family == AF_INET) return sendto(sock, data, size, 0, sa, sizeof(sockaddr_in));
    return -1;
}
client.reset(aoo::net::iclient::create(userPtr, client_send, boundUdpPort)); // port goes into the login's local addr
```

**Endpoint identity:** AOO matches sources/sinks by the `void *endpoint` *pointer*. SonoBus keeps one heap
`EndpointState` per `ip:port`, created on first packet (`findOrAddEndpoint`, SBP:2211) and never freed while
running. Do the same: stable pointer per remote address.

**Dispatch of an incoming datagram** (`doReceiveData`, SBP:2265-2413):
```cpp
int32_t type, id;
if (aoo_parse_pattern(buf, n, &type, &id) > 0 || aoonet_parse_pattern(buf, n, &type) > 0) {
  if (type == AOO_TYPE_SINK) {                 // "/aoo/sink/<id>/..." or compact "/d" (id == AOO_ID_NONE)
     if (id == AOO_ID_NONE) { for each peer: if (peer.sink->handle_message(buf,n,ep,endpoint_send)) break; }
     else  -> peer whose sink id == id (AOO_ID_WILDCARD -> all), also echo/latency sinks by id
  } else if (type == AOO_TYPE_SOURCE) {        // "/aoo/src/<id>/..."
     if (id == 0) dummySource->handle_message(...);           // blind-invite handshake source
     else -> peer whose source id == id (+ echo/latency sources)
  } else if (type == AOO_TYPE_CLIENT || type == AOO_TYPE_PEER) // "/aoo/client/..." "/aoo/peer/..."
     client->handle_message(buf, n, &sockaddr_in_of_sender);   // must be AF_INET
  // AOO_TYPE_SERVER: ignore
  notifySendThread();
} else if (buf starts with "/sb") handleOtherMessage(...);    // SonoBus extras, section 4
```
`aoo_parse_pattern` returns `AOO_TYPE_SINK` + `AOO_ID_NONE` for the compact data message `"/d"` (common.cpp:74-82).
Sinks must have `AOO_PROTOCOL_FLAG_COMPACT_DATA` set or sources keep using full `/aoo/sink/<id>/data`.

## 3. Connecting to the server and joining a group

```cpp
client->connect("aoo.sonobus.net", 10998, username, userPassword);  // SBP:1142; returns 1 if queued
// wait for AOONET_CLIENT_CONNECT_EVENT with result > 0, THEN:
client->group_join(group, groupPassword, isPublic);                 // SBP:1275 (C: aoonet_client_group_join[_public])
client->group_leave(group);  client->disconnect();  client->quit(); // teardown order SBP:1061-1064
```
Internals (client.cpp):
1. `connect()` stores `username`, MD5-hex(UPPERCASE) of the password, state `connecting`; only allowed from
   `disconnected` (returns 0 otherwise, and `disconnect()` returns 0 unless *connected*).
2. Client thread: TCP connect (5 s timeout, `TCP_NODELAY`, IPv4 `gethostbyname`), state `handshake`.
3. `send()` sends `/aoo/server/request` over UDP every 100 ms until the server's UDP `/aoo/client/reply s:ip i:port`
   (your public endpoint). Timeout 5 s (`AOO_NET_CLIENT_REQUEST_TIMEOUT`) -> `AOONET_CLIENT_DISCONNECT_EVENT`
   result 0 "timed out".
4. TCP `/aoo/server/login s:user s:md5pwd s:public_ip i:public_port s:local_ip i:local_port h:token` (random int64
   token for symmetric-NAT matching). Reply `/aoo/client/login i:status [s:err]` -> CONNECT event.
5. `group_join` sends `/aoo/server/group/join s:group s:md5(grouppwd) T/F:is_public`; reply -> GROUP_JOIN event.
Keepalive: TCP `/aoo/server/ping` and UDP `/aoo/server/ping` every 10 s (`AOO_NET_CLIENT_PING_INTERVAL 10000`).

No version string or client-ID check on the server: login only checks user/password (server.cpp:291-317). Users are
created on demand and **persist with their password**; same name already online -> `"access denied"`, same name with
a different password -> `"wrong password"`. Use a unique name (SonoBus defaults to the computer name /
full user name, SonobusPluginEditor.cpp:327-335) and usually an empty user password.

**Client events** (`aoonet_event_type`, aoo_net.h:93-107; handled in SBP:4163-4404):

| Event | Struct | SonoBus action |
|---|---|---|
| `AOONET_CLIENT_CONNECT_EVENT` | `aoonet_client_event` (`result`, `errormsg`) | result>0 connected; on pending reconnect, re-join last group |
| `AOONET_CLIENT_DISCONNECT_EVENT` | same | result==0 = lost (not user): start 1 s reconnect timer if in a group; peers are **kept** |
| `AOONET_CLIENT_GROUP_JOIN_EVENT` / `_LEAVE_EVENT` | `aoonet_client_group_event` (+`name`) | leave -> remove all peers |
| `AOONET_CLIENT_PEER_PREJOIN_EVENT` | `aoonet_client_peer_event` (`group`,`user`, address NULL) | UI only: server announced a peer, hole punching starts |
| `AOONET_CLIENT_PEER_JOIN_EVENT` | `aoonet_client_peer_event` (`address` = `sockaddr_in*` that answered, `length`) | **create peer + invite** (section 4) |
| `AOONET_CLIENT_PEER_JOINFAIL_EVENT` | peer event, no address | UDP punch failed after 5 s; UI only |
| `AOONET_CLIENT_PEER_LEAVE_EVENT` | peer event with address | `removeAllRemotePeersWithEndpoint` |
| `AOONET_CLIENT_ERROR_EVENT` | `aoonet_client_event` | log |
| `..._GROUP_PUBLIC_ADD/DEL_EVENT` | group event, `result` = user count | public group list (`group_watch_public(true)`) |

Copy strings/addresses out inside the handler: the library deletes the events right after the callback
(client.cpp:509-530). Note `aoonet_client::events_available()` always returns 1; just call `handle_events`.

**Reconnect** (SBP:4204-4215, 8835-8866): on unexpected disconnect with a joined group, a 1 s timer calls
`connectToServer(last host, port, user, pwd)` until connected; CONNECT then re-joins the group. P2P streams survive
server loss (`mRecoveringFromServerLoss` keeps peers).

## 4. Peer setup and the handshake real SonoBus apps expect

**Objects:** one **dummy `isource` with id 0** for the whole app (`mAooDummySource`, SBP:918; `setup(sr, block,
numInputs)` in prepareToPlay, SBP:6981). Per remote peer: **one `isink` and one `isource` with the same id `ourId`**
(lowest free integer >= 1, SBP:5976-5989), plus latency sink/source (`ourId + 20000`) and echo sink/source
(`ourId + 40000`) used only by the latency test. Peers are keyed by endpoint (one peer per ip:port).

**On `PEER_JOIN`** (`connectRemotePeerRaw`, SBP:4407-4445) when auto-connect is on:
```cpp
ep   = findOrAddRawEndpoint(e->address);                       // ip:port from the sockaddr_in
peer = doAddRemotePeerIfNecessary(ep, AOO_ID_NONE, user, group);  // creates + configures sink/source (below)
peer->sink->invite_source(ep, 0, endpoint_send);                // "special - use 0": invite their DUMMY source
peer->source->start();                                          // unless send-muted
updateRemotePeerUserFormat(-1, peer); sendRemotePeerInfoUpdate(-1, peer); sendBlockedInfoMessage(ep, false);
```
`invite_source` queues a single `/aoo/src/0/invite i:ourSinkId i:protocolFlags` sent on the next `sink->send()`
(sink.cpp:55-67, 1620-1638). There's no retry.

**Full handshake (A = you with id Na, B = SonoBus with id Nb):**
1. A: `sinkA(Na)->invite_source(epB, 0)` -> B's dummy source 0 raises `AOO_INVITE_EVENT` (`aoo_sink_event`: `id=Na`,
   `flags`). B (SBP:3499-3547): if connected to a server it only accepts if it already has a peer for that endpoint
   (`findRemotePeer(es,-1)`; else logs "Not reacting to invite from a peer not known in the group"), then
   `sourceB(Nb)->add_sink(epA, Na, endpoint_send)`, `set_sinkoption(epA, Na, aoo_opt_protocol_flags, &e->flags)`,
   `start()`, and **invites back** `sinkB(Nb)->invite_source(epA, Na)` (assumes our source id == our sink id).
2. A's source Na gets `AOO_INVITE_EVENT` (id=Nb) (SBP:3549-3578): `remoteSinkId = Nb; source->add_sink(ep, Nb,
   endpoint_send); set_sinkoption(..., aoo_opt_protocol_flags, &e->flags); start(); connected = true;` then send
   layout + peer info.
3. B's source starts sending `/aoo/sink/Na/format` -> A's sink raises `AOO_SOURCE_ADD_EVENT` (`aoo_source_event`
   id=Nb) (SBP:3707-3750): `remoteSourceId = Nb; sink->uninvite_source(ep, 0, endpoint_send)` (drop the bogus id-0
   entry) `; sink->invite_source(ep, Nb, endpoint_send)` (or uninvite if receive-muted). Ignore an ADD whose id is
   the dummy id 0.
4. `AOO_SOURCE_FORMAT_EVENT` (SBP:3751-3866): `sink->get_source_format(ep, id, fmtStorage)`; if channel count changed,
   `sink->setup(sr, block, max(outChans, nchannels))` under the sink lock; optional userformat via
   `get_sourceoption(ep, id, aoo_opt_userformat, buf, 1024)` (JUCE ValueTree binary, ignore it).
Both sides run this symmetrically; whichever invite arrives first wins and the other side's is ignored or deduped.
To interoperate you need: the dummy source 0 handling invites (step 1 as receiver), source INVITE handling (2),
sink SOURCE_ADD handling (3), and your own invite to their 0.

**Other source events** (`handleSourceEvents`, SBP:3455-3701):
- `AOO_UNINVITE_EVENT` (by remote sink id): `source->remove_all(); sendActive = false`.
- `AOO_CHANGECODEC_EVENT`: the remote asked for another format; with `set_respect_codec_change_requests(1)` the
  source already switched; SonoBus only copies the format to latency/echo sources and updates its format index.
- `AOO_PING_EVENT` (`aoo_ping_event` tt1/tt2/tt3): RTT = `aoo_osctime_duration(tt1, tt3)*1000`; used only if no
  `/sb/pingack` arrived (old peers).

**Sink events** (`handleSinkEvents`, SBP:3703-4108): `AOO_SOURCE_STATE_EVENT` (`state` STOP/PLAY -> recvActive),
`AOO_BLOCK_LOST_EVENT` (count -> drops + auto jitter buffer, section 6), `AOO_BLOCK_RESENT_EVENT`,
`AOO_BLOCK_REORDERED_EVENT`, `AOO_BLOCK_GAP_EVENT` (log), `AOO_PING_EVENT` (drives auto-decrease).

**SonoBus `/sb/...` messages** (raw OSC on the same UDP socket, SBP:2418-2860, built with oscpack):

| Address | Args | Required? |
|---|---|---|
| `/sb/ping` | `t:origTime` (NTP `aoo_osctime_get()`), sent every 2 s per peer (`PEER_PING_INTERVAL_MS`) | Reply strongly recommended |
| `/sb/pngack` | `t:origTime t:yourNow` sent back immediately | Reply to their ping; they compute RTT from it |
| `/sb/pinfo` | `b:` JSON blob `{"jitbuf":ms,"inlat":ms,"outlat":ms,"rec":bool}` | Optional (latency display) |
| `/sb/clayinfo` | `i:remoteSinkId b:` JUCE ValueTree binary (channel layout) | Optional; skip |
| `/sb/chat` | `s:group s:from s:targets s:tags s:message` | Optional (chat) |
| `/sb/blockedinfo` | `s:username T/F:blocked` | Optional |
| `/sb/reqlatinfo`, `/sb/latinfo`, `/sb/suggestlat`, `/sb/suggestgroup` | latency-match / group suggestion | Optional |

Minimal-interop ping handler (SBP:2575-2601):
```cpp
// on "/sb/ping": reply with /sb/pngack
osc::OutboundPacketStream o(buf, sizeof buf);
o << osc::BeginMessage("/sb/pngack") << osc::TimeTag(tt) << osc::TimeTag(aoo_osctime_get()) << osc::EndMessage;
endpoint_send(ep, o.Data(), (int)o.Size());
// on "/sb/pngack" (tt1, tt2): rtt_ms = aoo_osctime_duration(tt1, aoo_osctime_get()) * 1000
```
None of the `/sb` messages gate audio. The latency test (echo/latency sink+source ids +20000/+40000) is also
optional: without them, a SonoBus user's "measure latency" against you just fails.

**Per-peer configuration** (`doAddRemotePeerIfNecessary`, SBP:6022-6075):
```cpp
int32_t flags = AOO_PROTOCOL_FLAG_COMPACT_DATA;
sink->setup(sr, blocksize, outChans /*2*/);    sink->set_buffersize((int)buffertimeMs);
sink->set_option(aoo_opt_protocol_flags, &flags, sizeof(int32_t));
sink->set_dynamic_resampling(0);               // mDynamicResampling defaults false
setupSourceFormat(peer, source);               // section 5

source->set_packetsize(600);                   // RemotePeer::packetsize
source->set_ping_interval(2000);
source->set_respect_codec_change_requests(1);
source->set_dynamic_resampling(0);
```
Resend options are left at the library defaults: resend buffer 1000 ms, limit 5, interval 10 ms, max 16 frames per
call, redundancy 1 (aoo.h:76-99). SonoBus never changes them.

`formatInfoToAooFormat` (SBP:6313-6341):
```cpp
aoo_format_storage st; auto *f = (aoo_format_opus *)&st;
f->header.codec      = AOO_CODEC_OPUS;                          // "opus"
f->header.blocksize  = blocksize >= info.min_preferred_blocksize ? blocksize : info.min_preferred_blocksize;
f->header.samplerate = (int)sampleRate;                         // device rate
f->header.nchannels  = channels;                                // 1 for a mono send
f->bitrate           = info.bitrate * channels;                 // total bitrate
f->complexity        = 10;
f->signal_type       = OPUS_SIGNAL_MUSIC;
f->application_type  = OPUS_APPLICATION_RESTRICTED_LOWDELAY;
source->set_format(st.header);
// PCM: aoo_format_pcm *p; p->header.codec = AOO_CODEC_PCM; same header rules; p->bitdepth = AOO_PCM_INT16/INT24/FLOAT32
```
The Opus codec then validates (codec_opus.cpp:62-104): sample rate must be 8/12/16/24/48 k, otherwise **48000**
(the source resamples internally, e.g. 44.1 k device -> 48 k stream). Blocksize is clamped to [sr/400, 24*sr/400] and
**rounded down to 120 * 2^k** (e.g. 256 -> 240, 128 -> 120). Uses `opus_multistream_encoder_create` with one
uncoupled stream per channel. Sink and source both take `setup(sampleRate, currSamplesPerBlock, nchannels)` with the
device block size. SonoBus waits until the host block size is stable for 30 callbacks, then re-runs format/setup for
all peers and briefly mutes receive for 250 ms (SBP:7364-7378, 3289-3304).

## 6. Jitter buffer (sink buffer size), drops, latency

- Option: `sink->set_buffersize(int32_t ms)` (`aoo_opt_buffersize`; float ms is truncated). Default jitter buffer
  param `mBufferTime` = 0.001 s, so new peers start at **1 ms** with `AutoNetBufferModeAutoFull` (SBP:5999-6019;
  header defaults `defaultAutoNetbufMode = AutoNetBufferModeAutoFull`, `mAutoresizeDropRateThresh = 0.5`).
  `InitAuto` starts at 0 ms. While `buffertimeMs < 3` the peer starts **safety-muted** (`resetSafetyMuted`).
- Modes (`AutoNetBufferMode`): `Off`, `AutoIncreaseOnly`, `AutoFull`, `InitAuto`.
- **Increase** (`AOO_BLOCK_LOST_EVENT`, SBP:3890-3971): add `e->count` to drops; if the last drop was more than
  0.5 s ago and `1/deltatime > thresh` (0.5/s; 1.0/s in InitAuto) -> `buffertimeMs += 1000*blocksize/sr` (one block)
  and `set_buffersize` on sink/echo/latency sinks, then send `/sb/pinfo`. In AutoFull, a drop within 2 s of a decrease
  sets `netBufAutoBaseline = buffertimeMs` (floor for future decreases).
- **Decrease** (sink `AOO_PING_EVENT`, about every source ping interval, SBP:4006-4102): AutoFull only; if no drop for
  10 s and the last decrease was more than 10 s ago -> subtract one block, not below the baseline.
- **Init done**: 7 s without drops -> `autoNetbufInitCompleted`, unmute, reset counters (InitAuto stops adjusting).
- **Safety unmute** (`updateSafetyMuting`, SBP:2234-2263, run on each received packet while muted): after 0.5 s,
  unmute if the fast drop rate is between 0 and 2/s, or no drops for 0.75 s, or buffer > 15 ms.
- **Fill ratio**: before each `sink->process`, `sink->get_sourceoption(ep, remoteSourceId,
  aoo_opt_buffer_fill_ratio, &float, sizeof(float))` (0 = empty, 1 = full), smoothed (SBP:7829-7836).
- **Latency estimate**: `totalEstLatency = smoothPing + 2*buffertimeMs + blockMs` (SBP:3448), smoothPing from
  `/sb/pngack` RTT (only RTT < 600 ms is pushed into the average).
- Dropouts reported per peer: `dataPacketsDropped` (sum of lost counts), `dataPacketsResent` (resent events).

## 7. Mixing (processBlock, SBP:7815-7965)

Per peer, every callback, **after zeroing the buffer** (the sink leaves it untouched and returns 0 when it has nothing,
sink.cpp:410-476):
```cpp
uint64_t t = aoo_osctime_get();                 // once per callback, shared by all sinks/sources
for (auto &p : peers) {
    zero(p.work, sinkChans, n);
    p.sink->process(p.work /* float*[sinkChans] */, n, t);    // nsamples <= setup blocksize
    float g = (p.recvActive && !p.safetyMuted && !(anySolo && !p.soloed)) ? p.gain : 0.f;  // ramp from last gain
    // channel-group pan into the stereo mix; mono pan law: L = (1-pan) or 1, R = 1 or (1+pan),
    // times centerPanLaw + |pan|*(1-centerPanLaw), centerPanLaw = 0.596 (-4.5 dB) -> centred mono = 0.596 per side
    mixL += p.work[0] * g * 0.596f; mixR += p.work[0] * g * 0.596f;   // mono source; stereo: ch0->L, ch1->R
}
// send: one mono block per peer source (SonoBus sends the same input to each peer's own source)
for (auto &p : peers) p.source->process((const float **)&monoIn, n, t);
notifySendThread();
```
A mono source into a 2-channel sink fills only channel 0 (default `channelonset` 0). Gain is per peer (`gain`,
default `mDefUserLevel = 1.0`); mute = `recvAllow=false` -> `sink->uninvite_source(...)`, which also stops the remote
source from sending. Send mute = `source->stop()` / `start()`.

## 8. Gotchas

- **Port 10998**, not 10999 (section 0).
- **IPv4 only**: client `handle_message` rejects non-`AF_INET` (client.cpp:354), `copy_sockaddr` returns NULL for
  IPv6, `try_connect` uses `AF_INET` + `gethostbyname`. Bind your UDP socket `AF_INET`.
- **Version check**: AOO `/format` and `/invite` carry `make_version(flags)` = `(2<<24)|(0<<16)|(0<<8)|flags`;
  `check_version` only rejects a different **major** (common.cpp:21-37). No server-side version check.
- **Endianness**: OSC is big-endian on the wire; oscpack handles it if `OSC_HOST_LITTLE_ENDIAN` is defined.
- **Sample rate / block size**: sources and sinks resample internally (sink `resampler_.setup(decoder blocksize,
  sink blocksize, rates...)`); mismatched peer rates work. Dynamic DLL resampling is off by default in SonoBus; keep
  `AOO_TIMEFILTER_CHECK=0`.
- **NAT traversal is automatic** once you call `client->send()` regularly: each peer gets `/aoo/peer/ping h:token` to
  both its public and local address every 100 ms for up to 5 s; the first reply fixes the address and fires
  `PEER_JOIN` (client.cpp:1326-1418). Symmetric NAT: a ping carrying the peer's server-registered token from an
  unexpected address is accepted as the real address (client.cpp:396-418). After join, `/aoo/peer/ping` keeps the
  mapping alive every 10 s.
- **Unreachable peer**: after 5 s without a ping reply -> `AOONET_CLIENT_PEER_JOINFAIL_EVENT`, no audio. No relay or
  TURN in this AOO version. If audio later stops, there's no automatic teardown: the sink just stops producing
  (AOO_SOURCE_STATE_EVENT STOP), and the peer is removed only on `PEER_LEAVE` from the server.
- **Invite race**: a SonoBus app connected to a server ignores dummy-source invites from endpoints it doesn't know yet;
  because both sides invite on their own `PEER_JOIN`, the later invite completes the handshake. Your client must
  accept invites on its dummy source 0 too, or one direction may never set up.
- **Events are polled**: SonoBus handles AOO events every 20 ms on its own thread, so handshake steps take tens of ms.
  `handle_events` callbacks must copy data; event pointers die after return.
- `sink->process` returns 0 and leaves buffers untouched when nothing played; always pre-zero.
- `aoo_source_get_format` in aoo.h calls `set_option` (bug in the C wrapper); use the C++ `isource::get_format`.
- `AOO_MAXPACKETSIZE` = 4096: use that as the UDP receive buffer size (SBP:2268).
